Auth & access

Account-wide Auth administration requires a separate server-side, per-project Auth Admin integration.

No fake admin controls

This build intentionally does not call supabase.auth.admin from the browser. Those methods require a service-role secret and exposing it would give every visitor full administrative access. The Management API token is also never sent to the browser. User invites, role changes, and account deletion are not enabled in this initial release.

Next secure extension: create a server-side Auth Admin endpoint with an explicit per-project service key stored as an Edge Function secret, plus a narrower allowlist and audited actions.

Backend deployment checklist

  1. Create a dedicated control Supabase project; do not reuse your production app project.
  2. Add secrets SUPABASE_ACCESS_TOKEN, CONTROL_ADMIN_EMAILS, CONTROLLED_PROJECT_REFS, and DASHBOARD_ORIGIN in Edge Function secrets.
  3. Deploy supabase/functions/control-centre/index.ts with Supabase CLI.
  4. Enable GitHub Pages for main / root.
  5. Test using a disposable project ref before allowing production access.
